# סדר יום

מתכנן יום בעברית (RTL, מצב כהה): קו זמן אנכי, שבוע, משימות חוזרות, קטגוריות, גרירה להזזה ולשינוי משך, הוספה בדיבור, תזכורות, סנכרון בין מכשירים.
קובץ HTML אחד (`index.html`), בלי שלבי בנייה ובלי SDK. עובד גם בלי אינטרנט אחרי הטעינה הראשונה.

## קבצים
| קובץ | תפקיד |
|---|---|
| `index.html` | כל האפליקציה (HTML, CSS, JS) |
| `sw.js` | עבודה בלי רשת + קבלת התראות |
| `manifest.webmanifest`, `icon*.png/svg` | התקנה למסך הבית |
| `supabase/001_agenda_sync.sql` | טבלאות ופונקציות השרת (סנכרון + תזכורות) |
| `supabase/functions/agenda-push/index.ts` | שולחת את ההתראות בזמנן |
| `PHONE-TEST.md` | רשימת בדיקה על מכשיר אמיתי |

## הרצה
```
python3 -m http.server 8000     # מתוך תיקיית האב, ואז http://localhost:8000/agenda/
```
פריסה: מיזוג ל־`main` (GitHub Pages מגיש את `agenda/` מאותו מאגר).

## איפה נשמרים הנתונים
- **במכשיר:** `localStorage`, מפתח `agenda.v1`. זה המקור לאמת, והאפליקציה עובדת מלא גם בלי שרת.
- **בענן (רק אם מפעילים סנכרון):** פרויקט Supabase `demigod`, בטבלאות עם קידומת `agenda_` בלבד. לא נוגעים בשום דבר של האפליקציות האחרות באותו פרויקט.

## מודל האבטחה
- אין חשבון וסיסמה. **מפתח סנכרון** (26 תווים, 130 ביט) נוצר במכשיר. השרת שומר רק `sha256` שלו, ולא את המפתח.
- כל הטבלאות סגורות (RLS פעיל, אין מדיניות, אין הרשאות לטבלאות). האפליקציה יכולה רק לקרוא לפונקציות `agenda_*`, וכל אחת דורשת את המפתח.
- המפתח הציבורי של Supabase שבקוד (`sb_publishable_…`) מיועד להיות גלוי. הוא לא נותן גישה לנתונים בלי מפתח הסנכרון.
- כתובות התראות מתקבלות רק משירותי Push אמיתיים (Apple, Google, Mozilla, Windows).
- מפתח ה־VAPID הפרטי וסוד ההפעלה נשמרים ב־`agenda_config`, שלא נגיש לאפליקציה.
- **מי שמחזיק במפתח הסנכרון רואה את המשימות.** אין דרך לשחזר מפתח שאבד, אבל הנתונים נשארים במכשירים המחוברים.
- בהגדרות יש "מחק את הנתונים שלי מהענן".

## מגבלות שרת
1 MB לכל משתמש, עד 2,000 משתמשים, עד 30 חשבונות חדשים בשעה (לכל המערכת, חשבונות קיימים לא מושפעים), עד 800 תזכורות, עד 10 מכשירים להתראות.
ניקוי לילי (03:17) מוחק חשבונות שנוצרו ולא עודכנו מעולם, לא היו בהם פעולות 30 יום ואין להם מכשיר התראות. המכשיר ממשיך להחזיק את הנתונים ויוצר את החשבון מחדש בעת הצורך.
השינוי הזה מוגדר ב־`supabase/002_agenda_abuse_limits.sql`.

## איך עובדות ההתראות
1. המכשיר מחשב את כל התזכורות ל־30 הימים הקרובים ומעלה אותן (`agenda_set_reminders`).
2. `pg_cron` מריץ `agenda_tick()` כל דקה. אם יש תזכורת שהגיע זמנה, היא קוראת ל־`agenda-push`.
3. הפונקציה תופסת את התזכורות הלא־נשלחות בפעולה אחת (בלי כפילויות), שולחת ל־Web Push ומוחקת מנויים שפגו.
4. תזכורת שאיחרה יותר מ־30 דקות מסומנת כנשלחה ולא נשלחת.

אם לא פותחים את האפליקציה יותר מ־30 יום, התזכורות לסדרות חוזרות נגמרות עד לפתיחה הבאה.

## מגבלות מכשיר
- **iPhone:** התראות עובדות רק כשהאפליקציה מותקנת במסך הבית (iOS 16.4 ומעלה).
- **הקלטה:** נעשית על ידי הדפדפן או מערכת ההפעלה (גוגל או אפל). אפשר תמיד להקליד או להשתמש במיקרופון שבמקלדת. באפליקציה מותקנת באייפון ההקלטה לא תמיד זמינה.
- **ייצוא ליומן:** קובץ ICS, בלי תלות בשרת. בטלפון נפתח גיליון השיתוף.

## פתרון בעיות
| תסמין | בדיקה |
|---|---|
| לא מגיעות התראות | הגדרות ← סנכרון פעיל? ← "הפעל התראות" ← "שלח התראת בדיקה". באייפון: האם פותחים מהמסך הבית? |
| סנכרון "אין חיבור" | הכול נשמר במכשיר ויסונכרן כשיחזור החיבור. אפשר ללחוץ "סנכרן עכשיו". |
| מכשיר חדש לא רואה משימות | להזין את אותו מפתח בהגדרות ← "יש לי מפתח". |
| גרסה ישנה אחרי עדכון | לסגור לגמרי ולפתוח שוב. ה־service worker מביא גרסה חדשה כשיש רשת. |
